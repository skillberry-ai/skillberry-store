# PR #308 ("Memory Scale Down") — Review Feedback Triage

Source: [PR #308](https://github.com/skillberry-ai/skillberry-store/pull/308) — post-merge
review by Eran Raichstein (summary comment + 6 line-anchored comments), covering commits
`a82288a` → `8a241bd`.

Reviewer's bottom line: the memory work itself is sound and the measurements are honest
(≈70% RSS reduction, 812 MB → 232–239 MB). Changes #1–#4, #6 and #7 are acceptable as-is.
Essentially all behavioural risk is concentrated in the two changes that moved deployment
boundaries: the core-only image (#5) and the move of the UI into FastAPI (#8, #9–13).

Severity scale: **5 = critical**, 4 = high, 3 = medium, 2 = low, 1 = ignore / informational.

## Explicitly cleared by the review (no action)

- The path-traversal hole opened by `cd3ba00` is genuinely closed by the `is_relative_to(ui_root)`
  guard in `81cc4e9`; both raw (`/ui/../secret`) and percent-encoded (`/ui/%2e%2e%2fsecret`) forms
  were verified blocked.
- Deleting `modules/description_vector_index.py` loses nothing — only its own test referenced it.
- Registering `atexit`/signal handlers unconditionally in `main.py` is an accidental improvement:
  VMCP cleanup now runs on SIGTERM where it previously did not.
- The `PLUGIN_EXTRAS` alignment (#6) and the `[dev,pytest,plugins-all]` test extra keep `make test` whole.
